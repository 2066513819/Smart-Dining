# 食材成本问题说明与解决方案（不修改代码）
本文档说明两个常见问题，并给出**不修改代码**前提下的应对方法。
## 一、导入的食材成本表格名称与菜谱配方不一致，导致成本无法准确计算
### 1.1 原因说明

- 菜谱成本计算时，会从**菜谱文本**里解析出「食材名 + 用量」（如：`西红柿: 100g`、`鸡蛋 50克`）。
- 系统用**名称匹配**在您提供的「食材价格表」里查找单价：当前逻辑是「价格表里的名称」与「菜谱里的食材名」**包含关系**即视为匹配（`价格表名 in 菜谱名` 或 `菜谱名 in 价格表名`）。
- 若表格里写的是「番茄」「西红柿」「小番茄」，而菜谱里写的是「西红柿」，只有与「西红柿」能匹配上的那条价格会被用上；若表格里只有「番茄」而菜谱里只有「西红柿」，则**匹配不上**，该食材成本按 0 计算，导致总成本偏低。
因此：**名称不完全一致（包括同义不同名、简写、带单位/规格等）都会导致匹配失败，成本不准确。**
### 1.2 不修改代码的解决方法
1. **统一命名、与菜谱保持一致（推荐）**  
   - 在 Excel/成本表里，食材名称尽量与**菜谱/配方中写的名称完全一致**（如菜谱里写「西红柿」则表里也写「西红柿」）。  
   - 先整理一份「菜谱里出现的食材清单」，再按这份清单在成本表里命名，可最大程度避免漏匹配。
2. **在成本表里增加「同义名」多行（视当前系统是否支持多行同食材）**  
   - 若系统允许同一食材多条价格记录（按名称区分），可在导入表中为同一食材写多行、名称分别用「西红柿」「番茄」等，这样菜谱里无论写哪一种都能匹配到一条。  
   - 若当前导入逻辑会按名称去重、只保留一条，则仍以「与菜谱统一用同一名称」为主。
3. **维护一份「名称对照表」用于人工校对**  
   - 在 Excel 中单独做一个 Sheet，列出：菜谱用名、成本表用名、是否已对齐。  
   - 导入前按此表把成本表里的名称改成与菜谱一致，再导入。
4. **规格/单位写在单独列，名称列只写品类**  
   - 如菜谱里是「鸡蛋」「牛奶」，成本表里尽量用「鸡蛋」「牛奶」，不要用「鸡蛋（个）」「蒙牛纯牛奶」等，否则可能匹配不到。  
   - 规格、单位放在「单位」「备注」等列，名称列保持简洁、与菜谱一致。

4.1 **配方单位与价格表单位不一致（已支持）**  
   - 成本计算已支持配方中的「个、瓶、盒、袋、包、根、片、块、勺、瓣」等单位，会按默认比例换算成克再乘以单价（价格表仍按每克计价）。例如「鸡蛋 2个」按 2×50g 计。  
   - 价格表里的单位（如 500g、斤）在加载时已换算成每克价，无需改配方。

5. **使用系统「食材别名」功能（已实现）**  
   - 在「食材成本」中为某条价格添加**别名**后，配方里写别名也会按该条价格计算。例如价格表里是「番茄」，添加别名「西红柿」「小番茄」后，菜谱里写「西红柿: 100g」会按「番茄」的单价计算。  
   - 接口：`POST /ingredient_prices/{price_id}/aliases` 请求体 `{"alias_name": "西红柿"}`；列表接口返回的每条价格带 `aliases` 数组，前端已用别名参与成本匹配。

6. **配方简写、价格表带品牌/规格（已支持「最长匹配」）**  
   - 例如配方里写「鸡全翅」，价格表里是「益客冷冻鸡全翅」：系统会按**包含关系 + 最长优先**匹配，即「鸡全翅」会匹配到「益客冷冻鸡全翅」（配方名是价格名的子串时，在多个候选里选**价格名最长**的一条，更具体）。  
   - 匹配顺序：① 精确一致 → ② 配方名在价格名里（取最长）→ ③ 价格名在配方名里（取最长）。这样不会误匹配到更短的「鸡翅」等。

7. **可选：用正则别名**  
   - 若需要更灵活的一对多匹配，可为某条价格添加**正则形式的别名**（如 `.*鸡全翅.*`）。系统在精确/包含匹配都失败时，会尝试把这类别名当作正则去匹配配方里的食材名，匹配上则用该条价格。仅当别名中含有 `.*`、`|`、`(`、`[` 等时才按正则处理，普通文字仍按普通匹配。

## 二、普通用户食材成本页没有显示数据，但已经导入了食材
### 2.1 原因说明
系统里存在**两套与「食材成本」相关的数据**，用途和存储位置不同：
| 用途 | 数据来源 | 说明 |
|------|----------|------|
| **「食材成本」页面的列表** | 表 `ingredient_prices`，且按 **当前登录用户 ID** 过滤 | 只显示「当前用户」自己名下的食材价格；接口：`/ingredient_prices/my-prices`、`/ingredient_prices/count`。 |
| **Excel「导入成本表格」** | 写入的是 **`ingredient_l1_catalog` / `ingredient_l2_catalog`** 等分类目录表 | 与 `ingredient_prices` **不是同一张表**，导入成功后**不会**出现在「食材成本」页的列表中。 |

因此会出现：
- 普通用户（或管理员）在「食材成本」页点击「导入成本表格」并完成 Excel 导入；
- 导入接口返回「导入成功」；
- 但「食材成本」列表仍然为空。
原因就是：**列表读的是「当前用户的 ingredient_prices」**，而 **Excel 导入并没有往 ingredient_prices 表里写入当前用户的数据**，所以列表没有数据。  
另外，**食材成本列表是按用户隔离的**：A 用户导入或新增的食材价格，只会在 A 的账号下显示；B 用户登录后看到的是 B 自己的列表，所以 B 会看不到 A 导入的内容。
### 2.2 不修改代码的应对方法
1. **用「新增食材」逐条补全当前账号的单价**  
   - 在「食材成本」页面使用「新增食材」按钮，把本账号需要用的食材名称、单价、单位一条条录入。  
   - 这些数据会写入 `ingredient_prices` 且归属当前用户，列表中会正常显示，推荐时也会用这些价格做成本计算。
2. **确认当前登录的是哪个账号**  
   - 若您是用「管理员」账号导入的 Excel，再切换到「普通用户」账号查看，列表本来就是按用户分开的，普通用户下没有数据是预期行为。  
   - 若希望该普通用户也有数据，需要在该普通用户账号下，用「新增食材」或后续若有的「从导入结果同步到本账号」功能来补数据（当前版本不修改代码时，只能用手动「新增食材」）。
3. **Excel 导入结果的用途（当前实现）**  
   - 当前 Excel 导入主要写入的是分类目录表（用于供应商/分类管理），**不会**自动同步到「食材成本」列表所用的 `ingredient_prices` 表。  
   - 因此「已经导入了食材」指的是目录/分类里有数据，而不是「食材成本」页的列表里有数据；在未改代码的前提下，列表数据仍需通过「新增食材」在本账号下维护。
4. **后续可考虑的改进（需改代码）**  
   - 导入 Excel 时，在写入分类目录的同时，**同步写入当前用户的 `ingredient_prices`**（名称、单价、单位等），这样导入后「食材成本」列表会直接有数据；或  
   - 「食材成本」页增加「从供应商/分类目录同步到我的价格表」的按钮，把已导入的目录数据按当前用户写入 `ingredient_prices`。  
   - 以上都需要开发改动，此处仅作说明。

## 三、小结

| 问题 | 主要原因 | 不修改代码的应对 |
|------|----------|------------------|
| 成本不准确（名称不一致） | 成本计算按「名称匹配」；表格名与菜谱名不一致则匹配不到 | 成本表名称与菜谱配方统一；或同食材多行不同名称；维护名称对照表 |
| 普通用户食材成本没数据 | 列表读的是当前用户的 `ingredient_prices`；Excel 导入写的是另一套表，且按用户隔离 | 在本账号下用「新增食材」逐条维护；确认登录账号；理解「导入成功」不等于「列表有数据」 |

若后续需要通过改代码实现「导入结果同步到当前用户食材价格表」或「食材名称别名/映射」，可再在开发需求中单独说明。
