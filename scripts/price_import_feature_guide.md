# 供应商价格表导入功能使用说明

## 功能概述

现在系统的"菜谱制定"页面支持直接导入供应商提供的 Excel 价格表，自动提取食材成本数据并保存到数据库的 `l1_categories`、`l2_categories`、`ingredient_l1_catalog` 和 `ingredient_l2_catalog` 表中。

## 使用位置

**页面路径**: 菜谱制定 → 添加已有食材 → 导入成本表格

![功能位置示意图]
在推荐页面的"添加已有食材"区域，现在有两个按钮：
1. **预览表格** - 先预览 Excel 文件的数据结构和识别情况
2. **导入成本表格** - 正式导入数据到数据库

## 使用步骤

### 方法一：直接导入（适合熟悉格式的文件）

1. 点击 **"导入成本表格"** 按钮
2. 选择 Excel 文件（.xlsx, .xls, .csv）
3. 系统自动解析并导入数据
4. 查看导入结果提示

### 方法二：先预览再导入（推荐）

1. 点击 **"预览表格"** 按钮
2. 选择 Excel 文件
3. 系统显示预览对话框：
   - 文件信息（文件名、总行数）
   - 列名识别情况（一级分类、食材名称是否检测到）
   - 各列的映射结果
   - 前10行数据的原始内容和解析结果
4. 确认数据正确后，点击 **"确认并导入"**
5. 系统执行导入并显示结果

## 导入行为说明

### 分类处理
- **一级分类** (`l1_categories`):
  - 根据名称自动匹配现有分类
  - 不存在则自动创建新编码（从当前最大值+1开始）
  
- **二级分类** (`l2_categories`):
  - 根据名称和所属一级分类自动匹配
  - 不存在则自动创建（编码规则：前3位为一级编码 + 后2位自增）

### 食材价格处理
- **ingredient_l1_catalog**: 保存食材在一级分类下的价格和单位
- **ingredient_l2_catalog**: 保存食材在二级分类下的价格和单位
- **更新策略**: 如果 (食材名称, 分类) 组合已存在，会更新价格和单位

### 单位标准化
系统会自动将各种单位格式标准化：
- `斤` → `500g`
- `kg`、`千克`、`公斤` → `1000g`
- `克` → `g`
- 其他计数单位（个、只、瓶等）保持不变

## 常见问题

### Q1: 导入时提示"未检测到一级分类列"怎么办？

**A**: 请检查 Excel 表格的列名。系统支持多种列名格式，如"一级分类"、"大分类"、"分类"等。如果使用了特殊列名，建议修改为常用名称。

### Q2: 导入后发现分类不对怎么办？

**A**: 
1. 检查 Excel 文件中的分类名称是否正确
2. 如果分类已存在但匹配错误，可在数据库中手动调整 `l1_categories` 和 `l2_categories` 表
3. 重新导入时会根据名称自动匹配，不会重复创建

### Q3: 导入后食材价格在系统中如何使用？

**A**: 
1. 导入的食材价格会保存到 `ingredient_l1_catalog` 和 `ingredient_l2_catalog` 表中
2. 在菜谱制定时，系统会优先使用这些价格计算菜品成本
3. 如果推荐时提供了 `ingredient_prices` 参数，会覆盖数据库中的价格

### Q4: 可以导入多个月份的价格表吗？

**A**: 可以。每次导入都会更新现有价格，不会影响之前导入的数据。建议在导入文件名中标注日期，便于管理。

### Q5: 导入失败如何排查？

**A**: 
1. 使用 **"预览表格"** 功能检查列名识别情况
2. 查看浏览器控制台（F12）的网络请求响应
3. 检查后端日志文件 `app.log`
4. 确保 Excel 文件格式正确，没有合并单元格等复杂格式
